## 三、读取 CSV 并处理中文编码

原始 CSV 文件中包含中文商品名，直接用默认编码读取可能出现乱码。因此代码使用多编码尝试：

```python
def read_csv_with_fallback(filepath: str | Path) -> pd.DataFrame:
    filepath = Path(filepath)
    errors: list[str] = []
    for encoding in ("utf-8-sig", "gb18030", "gbk"):
        try:
            return pd.read_csv(filepath, encoding=encoding)
        except UnicodeDecodeError as exc:
            errors.append(f"{encoding}: {exc}")
    raise UnicodeDecodeError("unknown", b"", 0, 1, "; ".join(errors))
```

读取逻辑：

1. 先尝试 `utf-8-sig`，适用于带 BOM 的 UTF-8 文件。
2. 再尝试 `gb18030`，适用于中文 Windows 环境导出的 CSV。
3. 最后尝试 `gbk`，作为中文编码兜底。

对应原始输入文件：

| 文件 | 字段 | 含义 |
| --- | --- | --- |
| `GoodsOrder.csv` | `id`, `Goods` | 订单编号、商品名称 |
| `GoodsTypes.csv` | `Goods`, `Types` | 商品名称、商品类别 |

本步骤不直接生成输出文件，但它决定后续所有中文字段能否正确显示。

## 四、数据清洗：生成 clean_orders.csv 和 goods_with_types.csv

核心代码：

```python
def clean_inputs(orders: pd.DataFrame, goods_types: pd.DataFrame) -> tuple[pd.DataFrame, pd.DataFrame]:
    orders["id"] = pd.to_numeric(orders["id"], errors="raise").astype(int)
    orders["Goods"] = orders["Goods"].astype(str).str.strip()
    goods_types["Goods"] = goods_types["Goods"].astype(str).str.strip()
    goods_types["Types"] = goods_types["Types"].astype(str).str.strip()

    orders = orders.dropna(subset=["id", "Goods"]).drop_duplicates(["id", "Goods"])
    goods_types = goods_types.dropna(subset=["Goods", "Types"]).drop_duplicates(["Goods"])
    return orders, goods_types
```

清洗目的：

| 代码 | 作用 |
| --- | --- |
| `pd.to_numeric(...).astype(int)` | 把订单编号统一成整数，方便分组 |
| `.str.strip()` | 去掉商品名、类别名首尾空格 |
| `dropna()` | 去掉关键字段为空的数据 |
| `drop_duplicates(["id", "Goods"])` | 同一订单同一商品只保留一次 |
| `drop_duplicates(["Goods"])` | 商品分类表中同一商品只保留一条分类 |

随后在 `analyze_exploration()` 中合并类别：

```python
merged = orders.merge(goods_types, on="Goods", how="left")
merged["Types"] = merged["Types"].fillna("未分类")
```

这里使用 `left join`，保证订单表里的商品不会丢失。如果分类表中找不到某商品，就标记为“未分类”。

## 五、构建购物篮事务：从订单明细到事务列表

原始订单表是一行一个商品，但 Apriori 需要的是“一笔订单包含哪些商品”。因此代码按订单编号聚合：

```python
def build_transactions(orders: pd.DataFrame) -> list[list[str]]:
    grouped = orders.sort_values(["id", "Goods"]).groupby("id")["Goods"]
    return [list(dict.fromkeys(items)) for _, items in grouped]
```

示例转换：

```text
原始明细：
id  Goods
1   人造黄油
1   半成品面包
1   即食汤
1   柑橘类水果

转换后：
["人造黄油", "半成品面包", "即食汤", "柑橘类水果"]
```

关键点：

- `groupby("id")`：把同一个订单的商品放在一起。
- `dict.fromkeys(items)`：保留顺序的同时去重。
- 输出是 `list[list[str]]`，每个内部列表代表一个购物篮。

本次结果：

```text
交易订单数：9356
平均每单商品数：4.39
单笔订单商品数最小值：1
单笔订单商品数最大值：32
```

这一阶段主要为 0-1 矩阵和购物篮规模分析做准备。

```python
def encode_transactions(transactions: list[list[str]]) -> pd.DataFrame:
    encoder = TransactionEncoder()
    matrix = encoder.fit(transactions).transform(transactions)
    return pd.DataFrame(matrix, columns=encoder.columns_)
```

Apriori 算法需要布尔矩阵：

| 订单 | 全脂牛奶 | 其他蔬菜 | 面包卷 |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 1 |
| 2 | 0 | 1 | 0 |
| 3 | 1 | 1 | 0 |

含义：

- 行：订单。
- 列：商品。
- `1`：该订单购买了该商品。
- `0`：该订单没有购买该商品。

## 十、Apriori 参数对比：parameter_comparison.csv

实验报告要求调整最小支持度和最小置信度，因此代码设置参数网格：

```python
SUPPORT_GRID = [0.01, 0.015, 0.02, 0.025, 0.03, 0.05]
CONFIDENCE_GRID = [0.20, 0.30, 0.40, 0.50]
```

核心代码：

```python
for support in SUPPORT_GRID:
    frequent_itemsets = apriori(onehot, min_support=support, use_colnames=True)
    if not frequent_itemsets.empty:
        frequent_itemsets["length"] = frequent_itemsets["itemsets"].apply(len)

    for confidence in CONFIDENCE_GRID:
        if frequent_itemsets.empty:
            rules = pd.DataFrame()
        else:
            rules = association_rules(frequent_itemsets, metric="confidence", min_threshold=confidence)
        comparison_rows.append(
            {
                "min_support": support,
                "min_confidence": confidence,
                "frequent_itemset_count": int(len(frequent_itemsets)),
                "max_itemset_length": int(frequent_itemsets["length"].max()) if not frequent_itemsets.empty else 0,
                "rule_count": int(len(rules)),
                "max_lift": float(rules["lift"].max()) if not rules.empty else 0.0,
                "avg_lift": float(rules["lift"].mean()) if not rules.empty else 0.0,
                "max_confidence": float(rules["confidence"].max()) if not rules.empty else 0.0,
            }
        )
```

趋势解释：

- 最小支持度越高，频繁项集越少。例如支持度从 `0.010` 提高到 `0.050`，频繁项集从 `348` 个降到 `32` 个。

- 支持度较低时能发现更多细分组合，提升度上限也更高。
- 支持度较高时保留下来的多是大众商品组合，规则更稳定但惊喜度较低。

报告中可以这样描述：


`itemset_to_text()` 的作用：

```python
def itemset_to_text(items: Iterable[Any]) -> str:
    return "、".join(str(item) for item in sorted(items))
```

它把 `frozenset({"其他蔬菜", "柑橘类水果"})` 转成：

```text
其他蔬菜、柑橘类水果
```

### 输出 9：association_rules.csv

字段说明：

| 字段 | 含义 |
| --- | --- |
| `antecedents` | 前项，表示顾客已经购买的商品 |
| `consequents` | 后项，表示可能被带动购买的商品 |
| `antecedent_support` | 前项支持度 |
| `consequent_support` | 后项支持度 |
| `support` | 前项和后项同时出现的支持度 |
| `confidence` | 置信度，即买了前项后又买后项的概率 |
| `lift` | 提升度，衡量规则相对随机购买的增强程度 |
| `leverage` | 杠杆率，衡量实际共现概率比独立共现高多少 |
| `conviction` | 确信度，衡量规则预测后项的可靠程度 |
| `zhangs_metric` | Zhang 指标，衡量正负相关强度 |

常用指标公式：

```text
support(A -> B) = P(A 和 B 同时出现)
confidence(A -> B) = P(B | A) = support(A 和 B) / support(A)
lift(A -> B) = confidence(A -> B) / support(B)
leverage(A -> B) = support(A 和 B) - support(A) * support(B)
```

判断方法：

| 指标 | 解读 |
| --- | --- |
| `confidence` 越高 | 买了前项后购买后项的概率越高 |
| `lift > 1` | 前项和后项正相关 |
| `lift = 1` | 前项和后项近似独立 |
| `lift < 1` | 前项和后项负相关 |
| `support` 越高 | 规则覆盖的订单越多 |
